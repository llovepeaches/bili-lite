# 多端构建与运行指南

所有平台共用 `app/lib/` 下同一份 Dart 代码，`android/ ios/ web/ linux/ macos/ windows/` 是 `flutter create`
生成的原生壳，已补齐开发期所需的网络权限。

---

## 构建产物：统一由 GitHub Actions 生成

所有安装包都在 GitHub 托管 runner 上编译，本地只需保有源码：

| 产物 | Job | 运行环境 | 说明 |
| --- | --- | --- | --- |
| `BiliLite-<版本>-Android.apk` | `android` | `ubuntu-22.04` | Flutter 3.0.0 + JDK 11 + AGP 4.2.2，release 签名 |
| `BiliLite-<版本>-Windows-Setup.exe` | `windows` | `windows-2022` | Flutter 3.0.0 + Inno Setup 6 |
| `bili-lite-web-v<版本>.tar.gz` / `.zip` | `web` | `ubuntu-22.04` | Web 静态产物 + BFF 源码，解压后 `node server/src/index.js` 即可运行 |
| `BiliLite-<版本>-UNSIGNED.ipa` | `ios` | `macos-15` | 默认关闭，需 macOS + Apple 证书，见第 3 节 |

流水线定义在 `.github/workflows/build-installers.yml`，Flutter SDK 安装抽成
composite action `.github/actions/setup-flutter`。

触发构建：

```bash
gh workflow run build-installers.yml \
  -f flutter_version=3.0.0 \
  -f release_tag=bili-lite-v1.2.0 \
  -f publish=true
```

推送 `bili-lite-v*` tag 也会自动触发。产物既作为 Actions artifact 留存 30 天，
`publish=true` 时同时覆盖上传到对应的 GitHub Release。同一个 ref 的重复运行会自动取消旧任务。

### Android 签名

正式密钥以 Secret 形式存放在仓库，文件本身不入库：

| Secret | 用途 |
| --- | --- |
| `ANDROID_KEYSTORE_B64` | keystore 的 base64 编码 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 与 key 口令 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |

CI 还原后生成 `android/key.properties`（已被 `.gitignore` 忽略）；`app/build.gradle`
检测到该文件就使用正式签名，否则回退 debug 签名。当前正式密钥指纹：

```
SHA256: B1:26:09:9C:C2:66:9A:57:A0:88:27:94:17:95:28:76:7A:0D:AA:90:26:8C:44:49:FD:93:C1:BF:30:46:7F:8E
```

> 三个 Secret 缺失时流水线仍能跑通，但会用一次性 CI 密钥签名，产物**无法覆盖升级**。

## 0. 先启动 BFF（所有端都依赖）

```bash
cd server
node src/index.js
# 看到「访客身份 spi / 数据模式 B 站实时接口」即就绪
```

| 运行载体 | BFF 地址 | 配置方式 |
| --- | --- | --- |
| Web（BFF 同源托管） | 相对路径 `/api/*` | 自动，无需配置 |
| Android 模拟器 | `http://10.0.2.2:8787` | 自动 |
| iOS 模拟器 / 桌面 / Linux | `http://127.0.0.1:8787` | 自动 |
| **真机（Android / iOS / 其他设备）** | `http://<电脑局域网IP>:8787` | `--dart-define=BFF_URL=http://192.168.1.10:8787` |

真机示例（把 IP 换成电脑的局域网地址，手机与电脑需在同一 Wi-Fi）：

```bash
flutter run --dart-define=BFF_URL=http://192.168.1.10:8787
```

> 服务端默认 `HOST=0.0.0.0`，已监听所有网卡；若连不上先检查电脑防火墙是否放行 8787。

## 1. Web / PWA（推荐先跑这个）

```bash
cd app
flutter pub get
flutter build web --release --web-renderer html
# 回到 server 目录，BFF 会自动托管 app/build/web
```

打开 **http://localhost:8787**。浏览器地址栏可「安装应用 / 添加到主屏」，
`web/manifest.json` 已配置为 standalone + 粉色主题色，桌面与手机都能当独立窗口用。

调试模式：

```bash
flutter run -d chrome --dart-define=BFF_URL=http://localhost:8787
```

> Web 版由 BFF 同源托管时，API 走相对路径，天然无跨域问题。若单独用 `flutter run -d chrome`
> 启在别的端口，记得传 `BFF_URL` 指回 8787（BFF 已开启 `Access-Control-Allow-Origin: *`）。

## 2. Android

```bash
cd app
flutter build apk --release --dart-define=BFF_URL=http://192.168.1.10:8787
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

或直接连设备调试：

```bash
flutter devices
flutter run -d <device-id> --dart-define=BFF_URL=http://10.0.2.2:8787   # 模拟器
flutter run -d <device-id> --dart-define=BFF_URL=http://192.168.1.10:8787 # 真机
```

已配置：

- `android/app/src/main/AndroidManifest.xml` 里加了 `INTERNET` 权限（release 构建不会合并 debug manifest，必须写在 main）。
- `android:usesCleartextTraffic="true"` —— 本地 BFF 是 HTTP，Android 9+ 默认禁明文流量。

> 上架前请移除 `usesCleartextTraffic`，改用 HTTPS 的 BFF，并按需配置 `network_security_config.xml` 白名单。

## 3. iOS

需要 **macOS + Xcode**（沙箱为 Linux，无法编译 IPA，这里给出完整命令）。

```bash
cd app
open ios/Runner.xcworkspace      # 在 Xcode 里选签名 Team
flutter build ios --release --dart-define=BFF_URL=http://<Mac的局域网IP>:8787
flutter run -d <ios-simulator-id>   # 模拟器可用 127.0.0.1
```

已配置：`ios/Runner/Info.plist` 加入 `NSAppTransportSecurity`（`NSAllowsArbitraryLoads` +
`NSAllowsLocalNetworking`），允许开发期访问 HTTP 的本地 / 局域网 BFF。

> 上架前请删掉 `NSAllowsArbitraryLoads`，改成 `NSExceptionDomains` 精确白名单，且 BFF 走 HTTPS。

## 4. 桌面三端

| 平台 | 构建命令 | 额外要求 |
| --- | --- | --- |
| Linux | `flutter build linux --release` | `clang`, `cmake`, `ninja`, `libgtk-3-dev`, `pkg-config` |
| macOS | `flutter build macos --release` | Xcode + CocoaPods |
| Windows | `flutter build windows --release` | Visual Studio 2022（C++ 桌面工作负载） |

调试：`flutter run -d linux` / `-d macos` / `-d windows`，BFF 走 `127.0.0.1`，无需额外参数。

macOS 已配置：`DebugProfile.entitlements` 与 `Release.entitlements` 都加了
`com.apple.security.network.client`，否则 App Sandbox 会拦掉对 BFF 的请求。

桌面端布局会自动切换为左侧 NavigationRail + 4~5 列网格，详情页 ≥1100px 时变成「左信息 / 右评论」双栏。

## 7. 常见问题

**App 一直显示「数据没取到」**
→ 先看 `curl http://localhost:8787/api/health`；真机确认 `BFF_URL` 的 IP 正确且同一局域网。

**图片全裂**
→ 图片走 `/api/img` 代理且只允许 `*.hdslb.com` 域名；确认 BFF 可访问 B 站图床。

**详情页 / 搜索返回风控 HTML**
→ BFF 启动时会自动通过 `/x/frontend/finger/spi` 换取 `buvid3/buvid4`。若该接口不通会退回内置身份，
可在启动日志里看「访客身份」是 `spi` 还是 `fallback`。失败时会自动降级到 `mock-data.json` 快照。

**评论只有 3 条**
→ 未登录访客身份下 B 站的策略（实测 WBI 签名的新接口同样如此），非客户端缺陷。

**想完全离线演示**
→ `MOCK_MODE=1 node src/index.js`，所有接口返回 2026-11-09 抓取的真实数据快照。
